# Hospital Management System – Week 9 Lab 5

A JavaFX desktop application that manages patient registration records in a MySQL
database using JDBC. It supports Create, Read, Update, Delete and Search operations.



## Project structure

```
pom.xml                              
database.sql                         
src/main/java/module-info.java
src/main/java/application/
    Main.java                        
    PatientDAO.java                 
    Patient.java                     
src/main/resources/application/
    application.css                  
screenshots/                         
```



## Screen layout

| Region | Contents |
|---|---|
| `BorderPane` | Overall container |
| Top (`VBox`) | Title and subtitle |
| Center (`HBox`) | Patient Details form on the left, Patient Records on the right |
| Patient Details | `GridPane` of labels and inputs, plus an `HBox` with **Add Patient**, **Update**, **Delete**, **Clear** |
| Patient Records | Search field, **Search** and **Show All** buttons, and a `TableView` |
| Bottom | Status message (green for success, red for errors) |

## How each CRUD operation works

All database code is in `PatientDAO`. Every method opens a connection with
`DriverManager.getConnection()` and uses try-with-resources so the `Connection`,
`PreparedStatement` and `ResultSet` are always closed. User input is only passed through
`?` placeholders, never joined into the SQL string. Any `SQLException` is caught in
`Main` and shown in the status bar, so the application does not crash.

**Create – Add Patient.** `validateForm()` checks the fields first. If they are valid,
`getPatientFromForm()` builds a `Patient` object and `PatientDAO.addPatient()` runs
`INSERT INTO patients (...) VALUES (?, ?, ?, ?, ?, ?)` with `executeUpdate()`.
MySQL generates the `patient_id` (AUTO_INCREMENT). The table is then refreshed and the
form is cleared.

**Read – Show All.** `PatientDAO.getAllPatients()` runs a `SELECT` with
`executeQuery()`, loops through the `ResultSet` with `next()`, and creates a `Patient`
for each row. The list is shown in the `TableView`. This runs when the application starts
and when **Show All** is clicked.

**Update – Edit Patient.** Clicking a row in the table copies that patient into the form
(including the read-only Patient ID). After editing, **Update** validates the form and
`PatientDAO.updatePatient()` runs
`UPDATE patients SET ... WHERE patient_id = ?` using the selected patient's ID.

**Delete – Remove Patient.** After selecting a row, **Delete** shows a confirmation dialog.
Only if the user clicks OK does `PatientDAO.deletePatient()` run
`DELETE FROM patients WHERE patient_id = ?`. The table is then refreshed.

**Search – Find Patient.** `PatientDAO.searchPatients()` runs
`SELECT ... WHERE name LIKE ? OR phone LIKE ?`. The search text is wrapped in `%` and
passed as a parameter, so it matches any part of the name or phone number.

## Input validation

| Field | Rule |
|---|---|
| Patient ID | Read-only, generated by the database |
| Full name, Diagnosis | Required |
| Age | Required, whole number from 0 to 125 |
| Gender | Required: Female, Male, Non-binary or Prefer not to say |
| Phone | Required, digits/spaces/`+ - ( ) .` only, at least 7 digits |
| Admission date | Required, cannot be in the future (future days are disabled in the calendar) |
